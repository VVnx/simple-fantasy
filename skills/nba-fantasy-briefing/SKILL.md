# NBA Fantasy 每日简报

写一篇可以直接发布的简报，让读者知道每场发生了什么、谁贡献突出或明显伤害阵容、谁超出或低于预期、哪些变化会影响后续阵容、缺什么数据可以捡谁，并为每篇制作一张推荐的微信公众号封面。采用用户自己的球迷口吻，简短、有判断，允许少量自然的调侃。先读 [写法与研究](references/writing-and-research.md) 和 [惊喜+惊吓评估](references/surprise-and-scare.md)。

## 简版与用户来稿

用户2026年10月27日确认后续分档采用“今日牛人 → 今日惊喜哥 → 今日小惊喜哥 → 今日惊吓哥”，具体边界见[惊喜+惊吓评估](references/surprise-and-scare.md#用户确认的四档标准)。牛人不必每天硬选，小惊喜也可以收常规兑现、回暖及有价值的小数据，不再因为“明星基操”自动排除。用户提供的分档和顺序优先保留；球员、球队、当日数据和伤病仍需逐次核实。

用户要求按简版或其已发稿整理时，直接采用上述球员分档和“一些伤病更新”，不强加逐场简评、双句模板或重复数据附录。每人一张已核实的完整数据卡加一句到两句短评即可；图片已承载完整数据时，短评不必再逐项复述。每次新生成或完整重写简报后，默认调用独立的 [nba-fantasy-briefing-docx](../nba-fantasy-briefing-docx/SKILL.md) 技能，追加蓝色标题、紧凑数据卡、15MB以内的带图Word；用户明确只要文字或其他单一格式时遵从。整理既有稿件不自动新增封面或重写成完整版。

## 成稿逻辑

- 标题用当天最有辨识度的一件事，加“NBA Fantasy 每日简报 M月D日”，不加“含赛程”。
- 默认依次写三个主体部分：逐场简评、每日惊喜+惊吓球员从夯到拉、影响后续阵容的情况，文末增加“附录：惊喜+惊吓球员表现明细”。可用一句话开场，也可直接进入正文；阵容影响是每日重点。无比赛日只写有用的阵容动态，不凑比赛、榜单或附录。上传到旧版网站时按[交付和发布](references/publishing.md)适配分节标题。
- 逐场简评覆盖本期比赛日截至研究截止时间所有已结束比赛。每场点出明显打得好和明显打得差的人；没有突出表现就一两句带过，常规操作提一嘴。不要求每场都凑正反案例，约基奇常规水准的三双不自动升到最高档，有持有价值时可列入小惊喜。
- “每日惊喜+惊吓球员从夯到拉”参考红黑榜的持仓复盘逻辑：先核算9CAT+DD+A/T的当日综合收益与伤害，再结合常态、身价、近期趋势和实际角色判断。逐场筛查完整球员数据，覆盖明星、普通主力和替补；不限制人数、不设球队配额，也不强行填满档位。采用用户确认的牛人、惊喜哥、小惊喜哥、惊吓哥四档；常规兑现且有持有价值的表现可入小惊喜，不把普通三双自动抬到顶档。具体选人、排序与边界见[惊喜+惊吓评估](references/surprise-and-scare.md)。
- 每位上榜球员单独一个短段，通常两句：一句“今日表现简介”，交代关键产量、效率及代价；一句“上榜原因”，说明哪些项目带来净贡献/净伤害、相对预期的落差或有依据的角色变化。不能只贴数据或只给“夯/拉”标签，两位同队球员也分别写。不强制每人附加捡人/裁人建议，具体后续操作集中在阵容部分。
- 附录按惊喜+惊吓榜顺序列出全部上榜球员的完整表现明细，每人一行，含球队、名字、出场时间、得分篮板助攻、三分命中数、投篮、罚球、抢断盖帽失误；格式与命中/出手顺序见[写法与研究](references/writing-and-research.md#惊喜惊吓球员表现明细附录)。DD和A/T由核实数据判断，保留原数据行格式，不追加无穷大或虚构比率。核对附录与榜单人数、名单和比赛数据一致，没有上榜球员时省略附录。
- 阵容影响独立汇总当天值得更新的伤病、出场确认、复出与限时、首发及轮换变化，包括当天没有比赛的球队。优先写会改变之后出场、分钟、球权或加人决定的信息，明确“已确认”还是“预计/待定”。“确认缺席揭幕战”属于重点出场消息，不属于禁止生成的赛程分析。用户提及的人名和消息每次重新核实，不固化为事实。
- 伤病和轮换条目直接写“事实 → 谁受益、怎么受益 → 能补什么数据”，通常一两小段、三五句话就够。用用户的球迷口吻给判断，少铺垫；统计只留最能支持判断的一组，不逐项复述比赛数据。逐场简评和榜单里的同一事件，具体后续建议集中到阵容影响部分，避免重复长段分析。
- 不把“先观察、等确认、再看分钟、回来后重新评估”当成每条标配。同一个不确定条件只说一次，能用“库里若缺阵，梅尔顿……”说清，就直接接数据价值和建议。只保留会改变推荐的具体限制，如候选人自己有伤、机会明确短期；不靠删除“若、可能、有机会”把推断写成事实。
- 伤病条目必须分析同队受益者，不能停在“伤员继续持有、等待更新”。优先点名最有依据的1–2人，说清谁承接分钟、谁增加持球或出手，以及因此可期待的具体表现（如抢断、三分、助攻或篮板）。补位和接管球权可以是不同的人；不要把伤员的整份数据直接转给替补。证据不足时说明为什么暂时没有明确可捡对象，不用一句“先观察”省掉分析。
- 表现预期以已核实的数据特点和角色证据为依据：可写“时间增加后，抢断和三分值得期待”，不能无依据承诺每场抢断数或固定分钟。“缺抢断的可以捡”“深盟摸摸奖”“短租补篮板”就是有效建议，不必再接一套确认、观察、退出流程。具体写法见[写法与研究](references/writing-and-research.md)。
- 不写赛程、单周或双周场次数、背靠背、稀疏比赛日、赛程型加人建议，也不附赛程图或占位符。公众号赛程由用户自行撰写；最后一条有用的事实与建议之后直接接表现明细附录，不加结尾套话。用户另行明确要求赛程时再作为独立任务处理。
- 读者正文不放生成时间、统计口径教程、覆盖报告、执行清单、模型免责声明或重复总结。确有影响判断的不确定性，在该条里用一句话说清。
- 正文默认纯文字。正文内不残留 Markdown 标记、图片占位文字或“Image”。封面作为独立图片交付，不插入正文。网站详情的日期标题已有字段，正文不要重复一遍。

## 每次必须重新核实的内容

- 以用户所在时区的“今天”为发布日期；NBA比赛按 America/New_York 归属。记录实际研究截止时间与比赛覆盖日期到本地底稿。若请求“昨晚比赛”或特定比赛日，按该范围核验；不能因时差漏掉已结束比赛。
- 查当前赛季官方比赛清单、状态及已结束比赛的完整球员数据，逐场核对出场时间、效率和关键数据，不能只看高光新闻。常规赛还未开始或当天无比赛，可以写伤病/轮换简报，不能拿季前赛数据当常规赛。涉及季前赛时明确标注，判断以健康、角色和轮换证据为主。
- 伤病事实优先球队、NBA官方、教练或可靠记者原话；使用适用赛季的伤病报告。独立检查会影响后续阵容的新消息，不仅搜索当天参赛球队或已有比赛报道。用户点名的出场消息优先核实；训练负荷增加、教练乐观和正式可出场不是一回事。新闻时间不得晚于指定的历史截止时间。
- 推荐候选人前核对当前球队、位置与轮换、自己的健康状态，以及最近实际分钟/首发/持球证据。有新赛季样本时看近3–5场；没有样本则用“有机会”“可摸奖”等措辞体现判断强度，不把深度表或季前赛一场写成稳固角色，也不反复追加等待话术。
- 榜单与建议统一采用9CAT+DD+A/T：FG%、FT%、3PTM、PTS、REB、AST、ST、BLK、TO，加DD与A/T，共11项。前场篮板不作为独立计分项，也不拿它替代DD；可用于解释拼抢和角色，已计入REB的部分不重复奖励。两率结合出手量，TO与A/T分别审视，双双按单场实际达成计入；正文只提影响结论的项目。不能用高得分、双双或增加球权掩盖效率和失误代价。
- 用户没有提供联盟时，给条件建议，不捏造自由市场可用性或Yahoo持有率。对“亨特”“阿伦”等可能重名的称呼，在底稿记录已核实的标准英文名、球队；无法消歧则不作具体推荐。
- 用户示例中的人名、所属球队、替补顺序和伤病只是当次稿件材料，不能固化成后续事实。原示例末尾的赛程已被用户后续要求排除，不照搬。

## 封面、交付与发布

每篇新生成或完整重写的简报，默认交付一张推荐封面，不主动提供多个备选。读 [微信封面](references/wechat-cover.md)，使用可用的 imagegen skill 和内置图片生成工具制作。精简措辞或补充轮换建议、且主题与日期未变时，沿用已有匹配封面；用户明确只要文字时遵从。

正文定稿后默认再运行 [带图Word导出](../nba-fantasy-briefing-docx/SKILL.md)，把DOCX与正文、独立封面一并交付，方便用户向其他平台复制排版。Word使用用户指定的蓝色标题与紧凑头像数据卡，不能只承诺下次会附上。此步骤不创建定时任务，也不替代或授权网站发布。

保存简报纯文字和简短的来源底稿：新闻URL与发布时间、事实/判断依据、候选人身份、研究截止时间、缺失项；另存封面图片、最终提示词和实际尺寸。无需为这类短稿抓取或附加赛程统计。底稿保留研究细节，读者稿保持利落。若需全比赛数据，可复用同级 `nba-fantasy-daily/scripts/fetch_day.py` 和 `fetch_history.py`；无需为了三条休赛日新闻强行产出全员统计表。

交付前按[惊喜+惊吓评估](references/surprise-and-scare.md#完整覆盖与交付检查)复查每场完整数据：突出的正向贡献、负向伤害和预期落差是否漏人，每位上榜球员是否都有今日表现简介和一句具体上榜原因，DD、TO、A/T及两率出手量是否改变结论。再检查会影响后续阵容的消息是否遗漏，伤病条目有没有同队受益者或有依据的“暂无明确对象”、机会来自哪里、可能贡献哪些数据。补齐关键分析后，再删掉重复的条件、笼统提醒和结尾复述；研究卡片要完整，读者稿只留有用的判断。

交付与网站上传见 [交付和发布](references/publishing.md)。除非用户要求，生成稿件不自动改写现有文章，不自动发布或创建定时任务。用户明确要求上传时，按目标仓库 `AGENTS.md` 与 `docs/BRIEFINGS.md` 使用受保护接口，上传后逐字回读核对。原有“只有授权发布者能写入”的约束保持不变。
