# NBA Fantasy 带图 Word

把定稿和已核实的球员数据整理成方便复制到其他平台的DOCX。作为 `nba-fantasy-briefing` 的交付步骤使用，也可单独整理用户来稿。先阅读可用的documents技能并用其依赖解析与逐页渲染流程；本技能中用户指定的蓝色标题优先于通用文档的黑色标题默认值。

## 固定的展示约定

- 文档标题和各级分节标题使用参考图的蓝色 `#2A77BF`，不加标题下划线、分隔线或水印。正文黑色，保留用户的球迷口吻、昵称、分档和顺序。
- 球员卡为项目现有生成器的2400×200紧凑横条。数据文字不缩小来挤版；头像先去掉透明边缘，再贴合左侧区域，保留头部，不留大块上下空白。禁止拉伸球员照片或照抄参考图中的球员事实。
- 每张卡紧跟对应短评，图和点评一起分页。卡片段落无多余空行，图与点评约3pt间距，球员之间约8pt间距。默认沿用A4横向以保证横条数字清晰；用户另有页面要求时调整物理宽度并重新检查。
- 全部点评球员各配一张卡，图片承载完整数据时不再添加重复的全员数据附录。完整版的逐场简评、阵容影响等已定稿正文仍保留；简版不自动扩写。无比赛或无榜单时正常导出有用正文，不凑球员卡。
- 最终DOCX严格小于15,000,000字节。需要嵌入中文字体时只嵌文中字符和常用ASCII，优先保留原PNG清晰度，不能为省体积直接删除中文字库造成乱码。

## 输入与执行

输入约定和命令见 [导出输入](references/input-and-commands.md)。新建文章的比赛、伤病和分档由上游每日简报流程核实；本技能不依据短评猜球员或补齐统计，缺少身份/数据时回查原始比赛记录或询问用户。用户已确认的原稿结构优先。

1. 从已定稿正文准备输入JSON。用标准英文名或球员ID绑定卡片，保留该场球队与美东比赛日期。来源与研究截止时间留在本地底稿。
2. 用 `scripts/render-cards.mjs` 复用目标项目的 `lib/player-card-image.ts` 和尺寸常量，生成紧凑卡片、emoji素材及 `rendered.json`。头像可复用已核实的本地缓存。脚本不发布网站、不改线上数据。
3. 用 `scripts/build-docx.py` 输出DOCX，传入已解析的文档运行时、静态中文字体和必要的字体子集辅助包。脚本保留可编辑正文并嵌入图片，自动进行字库子集与15MB检查。
4. 按documents技能渲染并打开每页PNG，确认标题蓝色、中文完整、数字和头像清晰、卡片和点评未拆开、照片头部未裁掉。逐人核对名单、顺序及卡片内容，检查实际文件字节数后只交付最终DOCX。

## 与每日简报的连接

每次新生成或完整重写每日简报后运行本技能，和正文、独立封面一并交付。用户明确只要文字或其他单一格式时遵从。窄幅修订可更新已有匹配DOCX，不强行重复研究或制作新封面。运行本技能不等于授权发公众号、发布网站或创建定时任务。

此技能的项目副本与已安装个人副本保持同步。交付当前文章只需本地导出，不需要网站源码部署；若用户明确要求网站上线则另按站点发布流程处理。
