# 每日简报

`/briefings` 显示按日期倒序排列的简报列表，仅展示日期和标题。点击条目进入 `/briefings?date=YYYY-MM-DD` 查看全文、推荐封面及封面下载，可返回列表或阅读相邻简报。没有封面的文章正常显示文字。列表每页 30 篇，通过 `before=YYYY-MM-DD` 浏览更早内容。正文为 UTF-8 纯文字，保留换行；HTML/Markdown 不作富文本渲染。历史数据保存在 Sites D1 `DB` 的 `daily_briefings` 表，日期唯一，重新部署不清空数据。

## 正文风格

直接写比赛、球员动态和 Fantasy 判断。赛程由用户自行撰写到公众号，简报不生成赛程、单周或双周场次数分析、赛程型加人建议。避免重复页面标题、生成时间、口径说明、数据覆盖说明、执行清单和收尾套话。必要的不确定性放在对应球员的一句话里；来源与核验底稿保存在本地，不占用简报正文。

生成简报优先使用个人 skill `nba-fantasy-briefing`，正文默认包含以下三个部分：

1. **逐场简评**：覆盖本期比赛日截至研究截止时间全部已结束比赛，特别好、特别差的表现展开，没有突出表现就一两句带过。常规操作提一嘴，例如约基奇常规水准的三双；不要求每场都出现惊喜，也不强行配一好一差。
2. **每日惊喜球员从夯到拉**：汇总当天所有明显超出或低于自身正常预期的球员，从正面惊喜排到负面惊喜，每人一句关键数据和判断。结合效率、失误及角色，不能只按总得分排；不凑人数或档位，没有惊喜就简短说明。
3. **影响后续阵容的情况**：每日重点，独立核查新伤、确认缺阵、复出及限时、首发与轮换变化，包括当天没比赛的球队。明确确认与推测，写清谁增加或减少分钟、球权、出手，以及具体数据与操作建议。确认缺席揭幕战这类消息属于重点出场信息，不属于赛程分析；用户举例的人名和状态必须每次重新核实。

文末增加“附录：惊喜球员表现明细”，按惊喜榜顺序覆盖全部上榜球员，每人一行：`球队 球员 P分R板A助攻 3PM记三分 投篮FGA投FGM中 罚球FTM/FTA S抢断B盖帽T失误`。投篮先出手后命中，罚球先命中后出手；零值保留，未出手罚球写0/0。球队与各项数字取该场核实数据，不照搬示例数值；没有惊喜球员时省略附录。

无比赛日只写有用的伤病与轮换动态。逐场简评、榜单和阵容影响之间避免重复长段文字，详细轮换建议集中在第三部分，沿用“事实 → 轮换机会 → 具体数据与操作建议”的写法。比赛清单、完整球员数据和新闻来源用于核验，附录只列惊喜榜球员，不附全员数据表。

每篇配一张推荐的微信公众号横版封面（约2.35:1），正文与封面分开交付。沿用用户自然的球迷口吻，重新核实当前球队、候选替补和健康状态，不把示例稿中的球员固化成规则。需要完整比赛数据日报时使用 `nba-fantasy-daily`。

赛程导出是独立工具，不作为简报skill的默认步骤。赛程页先选择单周或双周及周次，再点击“导出单周图片”或“导出双周图片”，下载包含全部30队的高清PNG。双周按页面布局横向显示14天，显示两周总场次；导出沿用页面当前的场次排序。封面和赛程图片独立交付，纯文字简报接口不接收图片。

## 球员数据卡片

`/player-cards` 提供一名球员一张的单场数据卡，简报详情可直接进入对应比赛日。日期选择按美东比赛日，卡片显示比赛对应的北京时间日期；默认选择北京时间昨天对应的比赛日。可查找当日球员、修改显示名称和短评、切换球队配色或灰蓝，下载与预览一致的 1080 × 1350 PNG。

数据包含得分、篮板、助攻、三分命中数及命中/出手、投篮和罚球命中/出手与命中率、抢断、盖帽、失误。只读取 ESPN 已完赛且通过场次、日期、得分与投篮校验的记录；缺失数据不补零，未出场球员不生成卡片。球队采用该场记录；头像使用固定 ESPN 图片源，加载失败时明确提示并提供重试。

## 推荐封面

封面原图保存在 `public/briefing-covers/`，由 `lib/briefing-covers.ts` 按文章日期登记路径、替代文字与实际像素尺寸。详情页显示完整比例的封面，下载按钮直接下载原图；列表保持日期和标题布局。封面不拼入纯文字正文，不通过正文上传接口传送。

用户要求同步网站且有新封面时，将确认后的图片复制到该目录、登记对应日期，再通过 Sites 流程部署图片和页面。保持原图比例并核实中文及日期；同日更换图片可使用版本文件名。正文仍通过受保护接口发布，无需为只改正文而部署源码。发布后检查对应详情页及图片地址均可访问。

## API

- `GET /api/briefings`：最新简报及相邻日期；没有内容时 `briefing: null`。
- `GET /api/briefings?date=YYYY-MM-DD`：指定日期及相邻日期，没有内容仍返回空值。
- `PUT /api/briefings?date=YYYY-MM-DD&title=可选标题`：发布或更新当天简报。请求体是纯文字，`Content-Type: text/plain; charset=utf-8`，最大 64 KiB。默认标题“每日简报”，日期为编辑指定的简报归属日。NBA 比赛日报通常采用美东比赛日，页面更新时间采用北京时间。
- 发布必须在 `Authorization: Bearer <token>` 携带发布凭证。匿名访问、访客登录、Cookie、伪造身份头、URL 参数均不授权写入。未配置返回 503；凭证错误返回 401；日期、标题或正文错误返回 400；过大返回 413；媒体类型错误返回 415。所有响应不缓存。
- 日期是主键；重试相同内容不会重复创建，也不改变更新时间。修改正文/标题会更新该日期，保留首次创建时间。此版本保留每日历史，不保留同一日的修改版本。

## 发布凭证

当前发布凭证采用本项目 Sites 管理接口 `get_site` 返回的 `siwc_bypass_bearer_token`。发布接口**自行校验**该凭证的 SHA-256，服务端秘密环境变量名为 `BRIEFING_PUBLISH_TOKEN_SHA256`。公开网站不能只依赖 Sites 外层访问控制。上传使用标准 `Authorization` 头，不能仅用会被平台消费的 `OAI-Sites-Authorization` 头代替应用层认证。

凭证由有权管理此 Site 的用户通过 Sites 工具取得。它不标识某个模型实例；这里的“只有助手上传”实际表示拥有此管理凭证的授权发布者可上传，网站普通访客不可上传。源代码、浏览器、仓库、命令行参数与文档均不包含凭证。若 Sites 凭证轮换，需由站点管理者通过原生 Sites 环境变量工具更新 SHA-256 并按平台要求重新部署；不要在失败后取消认证。

后续在用户要求发布简报时：

1. 读取 `.openai/hosting.json` 的项目 ID，用 Sites `get_site` 获取当前网站地址及服务凭证，仅保存在会话内存中。
2. 将待发布的纯文字保存为本地 UTF-8 文件。检查日期及内容；不要把演示文本发布到正式网站。
3. 从本项目执行 `npm run briefing:publish -- --site <current_live_url> --date YYYY-MM-DD --file <绝对路径> [--title <标题>]`，使用带终端的执行会话。
4. 看到 `Ready for credential JSON on stdin (input is hidden).` 后，通过标准输入发送一行 `{"token":"<会话内凭证>"}`。不要通过命令行、环境文件或日志传递/打印凭证。
5. 脚本在上传后回读核对内容，返回 `verified: true` 及简报链接后才报告成功。请求不跟随重定向，避免凭证发往其他主机。失败可能发生于保存后，请先回读再决定是否重试。

## 本地及部署

`.openai/hosting.json` 声明 D1 绑定 `DB`。`db/schema.ts` 定义表，`npm run db:generate` 生成 `drizzle/` 迁移；迁移只改结构，正式部署由 Sites 应用。数据库绑定和秘密值通过 Worker 的请求上下文传递，避免不同请求串用。

先构建以生成 Wrangler 配置，再按照 Sites 技能的本地 D1 步骤应用生成的 SQL。本地预览可使用独立测试凭证的 SHA-256。不能使用正式凭证做浏览器测试。普通 Next.js / Vercel 环境没有 Sites D1，简报显示不可用并返回 503，其他工具不受影响；迁移到 Vercel 时必须另接持久化数据库及运行时认证配置。

此功能仅提供阅读与上传，不会自行生成或定时发布简报。
